# DMAIC Playbook — 五阶段详细指南

> 6 Sigma 项目核心方法论。每个阶段的目标、关键问题、产出、判断标准。

## D — Define（定义）

**目标**：清晰定义问题、范围、目标、团队、干系人。

**关键问题**：
1. 问题是什么？（症状 vs 根本原因 — 我们现在定义的是症状）
2. 谁受影响？（客户是谁 — 内部客户也算）
3. 影响有多大？（量化基线 — 不良率 / 周期 / 成本 / 满意度）
4. 项目的范围是什么？（在范围内 / 范围外）
5. 目标是什么？（可量化、有时间限制）
6. 团队是谁？（Champion / Black Belt / Green Belt / 成员 / 干系人）
7. 为什么现在做？（商业论证）

**核心交付物**：
- 项目章程（charter）— 一页纸最高决策
- SIPOC — 流程全景图（Supplier → Input → Process → Output → Customer）
- VOC/CTQ 树 — 客户声音 → 关键质量特性
- 项目计划 — 时间表 + 里程碑

**判断能否进 M**：
- ✅ 项目章程已签字（Champion）
- ✅ SIPOC 完整（5 步都有）
- ✅ VOC/CTQ 至少 3 个 CTQ 已量化
- ✅ 项目计划有明确 D-M-A-I-C 里程碑

---

## M — Measure（测量）

**目标**：量化当前过程，建立基线，验证测量系统可靠。

**关键问题**：
1. 测量什么？（CTQ 选定 → 量化指标）
2. 怎么测量？（现有测量系统、量具、操作员）
3. 数据收集计划：谁、何时、何地、多少样本、什么频率
4. 测量系统可靠吗？（MSA — GR&R、偏倚、线性、稳定性）
5. 当前过程能力是多少？（Cp、Cpk、Pp、Ppk）
6. 数据分布形态？（正态？偏态？）

**核心交付物**：
- 数据收集计划（DCP）
- MSA 计划 + 结果
- 基线数据（CSV）
- 过程能力报告（Cp/Cpk）
- 数据分布 + 正态性检验

**统计工具**（来自 `scripts/stats.py`）：
- `capability()` → Cp/Cpk
- `normality_test()` → Shapiro-Wilk
- `sample_size_*()` → 样本量计算
- 控制图初稿（I-MR 或 Xbar-R）

**判断能否进 A**：
- ✅ MSA 通过（GR&R < 30%，通常 < 10% 优秀）
- ✅ 样本量满足统计功效（power ≥ 0.8）
- ✅ 过程能力已量化（Cpk 基线值记录）
- ✅ 数据已收集、保存、可追溯

---

## A — Analyze（分析）

**目标**：找出根本原因（root cause），不是表面原因。

**关键问题**：
1. 数据告诉我们什么？（趋势、异常、相关性）
2. 哪些因素影响 CTQ？（潜在 X's）
3. 关键少数 vs 有用多数（Pareto 80/20）
4. 因果链是什么？（鱼骨图 + 5 Why）
5. 哪些因子是真正重要的？（假设检验验证）
6. 风险评估（FMEA — 失效模式 × 影响 × 严重度）

**核心交付物**：
- 鱼骨图（Ishikawa 6M：Man/Machine/Material/Method/Measurement/Environment）
- 5 Why 分析（每个潜在根因）
- Pareto 分析（缺陷类型、客户投诉、设备停机原因）
- 假设检验结果（t 检验 / ANOVA / 卡方 / 回归）
- FMEA 表（严重度 S × 频度 O × 探测度 D = RPN）

**统计工具**：
- `t_test_*()` / `anova_oneway()` / 回归
- `pareto()` → 80/20 累计
- 相关性矩阵 → 找 X-Y 关系

**判断能否进 I**：
- ✅ 根本原因已识别（不是症状）
- ✅ 数据支撑结论（不是猜测）
- ✅ FMEA 已完成（关键失效模式有 RPN 评分）
- ✅ Pareto 显示关键少数（聚焦 20% 的原因）

---

## I — Improve（改进）

**目标**：生成、筛选、实施解决方案，验证改进效果。

**关键问题**：
1. 对每个根因，能想到哪些解决方案？
2. 哪些方案值得深入？（成本、可行性、效果）
3. 怎么选最佳方案？（多准则决策矩阵）
4. 试点方案怎么设计？（地点、时间、样本、成功标准）
5. 试点结果怎么样？（对比基线、统计显著？）
6. 是否需要 DOE 优化参数？（因子水平 + 响应）

**核心交付物**：
- 方案生成清单（每根因 ≥ 3 方案）
- 方案选择矩阵（多准则评分）
- 试点计划（Pilot Plan）
- 试点结果分析
- DOE 结果（如果做了）
- 改进后过程能力（Cpk 提升）

**统计工具**：
- `doe_factorial()` → 主效应 + 交互
- 改进前后对比（t 检验）

**判断能否进 C**：
- ✅ 试点成功（达到预期效果）
- ✅ 改进后 Cpk 显著提升（目标 ≥ 1.33 工业，≥ 1.67 优秀）
- ✅ 解决方案可标准化、可复制
- ✅ 干系人认可

---

## C — Control（控制）

**目标**：保持改进成果，文件化、标准化、移交运营。

**关键问题**：
1. 关键控制点是什么？（KCP / CTQ 控制限）
2. SPC 怎么部署？（控制图选型、抽样规则）
3. 反应计划是什么？（超出控制限怎么办）
4. 文档怎么更新？（作业指导书、SOP、PFMEA）
5. 培训谁？（运营团队）
6. 收益怎么追踪？（硬性 / 软性 savings）
7. 项目怎么结项？（A3 报告 + 移交）

**核心交付物**：
- 控制计划（Control Plan）
- SPC 图表 + 反应计划
- 更新后的 SOP / 作业指导书
- 培训记录
- 收益追踪表（项目期 + 后续 6/12 月）
- A3 总结报告

**统计工具**：
- 控制图（I-MR / Xbar-R / p-chart / u-chart）
- 过程能力再确认（Cpk 持续监控）

**结项标准**：
- ✅ 控制计划已发布
- ✅ SPC 已上线运行 ≥ 4 周
- ✅ 文档已更新
- ✅ 培训已完成
- ✅ 收益已追踪 ≥ 1 个月
- ✅ A3 报告已签字
